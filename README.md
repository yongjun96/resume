# 김용준 이력서 / 경력기술서 정적 사이트

빌드 도구 없이 파일만 올리면 바로 게시되는 정적 HTML 사이트입니다.

**레이아웃**은 초판 PDF 3종(`이력서.pdf`, `경력기술서_짧은버전.pdf`, `경력기술서_긴버전.pdf`)을 그대로 옮겼고,
**내용**은 이후 작성한 개정본(`이력서_김용준_개정본.md`, `경력기술서_김용준_개정본.md`)을 정본으로 삼아 갱신했습니다.
핀게이트 프로젝트 상세는 각 프로젝트별 상세 기록 문서를 근거로 작성했습니다.

> **웹 문서가 최신입니다.** `assets/pdf/`의 PDF는 갱신 이전 판이라 핀게이트 항목이 다릅니다.

## 구성

```
index.html            # 랜딩 페이지 (3개 문서 카드)
resume.html           # 이력서              (인쇄 시 A4 3p)
career-short.html     # 경력기술서 짧은 버전  (인쇄 시 A4 7p)  — 프로젝트 7건
career-long.html      # 경력기술서 긴 버전    (인쇄 시 A4 16p) — 프로젝트 11건
assets/
  css/style.css       # 공통 스타일 (원본 PDF의 섹션 라벨 색상값 그대로 사용)
  img/                # 프로필 사진 + PDF에서 추출한 아키텍처 구조도 4종
  pdf/                # 초판 PDF 3종 (참고용, 내용은 웹 문서가 최신)
```

## 원본 대비 재현한 요소

- `Info` / `Career` 대형 워터마크 제목, 인적사항 헤더 + 프로필 사진 + 굵은 하단 구분선
- 섹션 라벨 색상 (원본 PDF에서 추출한 실제 값)
  - 짧은 버전 : `[개요]` `#0c18a8` / `[문제]` `#0b786c` / `[해결]` `#841884` / `[문제 분석 및 해결]` `#a82448` / `[성과]` `#1860d8`
  - 긴 버전 : `[Why?]` `#5448d8` / `[Trouble shooting]` `#c03c54` / `[Solution]` `#a87854` / `[Result]` `#306c48`
- Outbox / Outbox Polling / Inbox / 전체 구조도 이미지 (PDF 삽입 이미지를 그대로 추출)
- GitHub · Blog 하이퍼링크

웹 가독성을 위해 조정한 부분은 다음 두 가지입니다.

- 구조도 이미지는 원본 비율을 유지하되 약 1.8배 확대
- 상단 문서 이동 내비게이션 추가 (인쇄 시 자동으로 숨김)

## GitHub Pages로 게시하기

로컬 커밋까지는 준비되어 있습니다. 남은 것은 원격 저장소 생성과 push 두 단계입니다.

**1. GitHub에서 빈 저장소를 만듭니다**

<https://github.com/new> 에서 이름을 `resume`로 지정하고, README와 .gitignore는 **추가하지 않은 채** 생성합니다.
(공개 여부는 Public이어야 GitHub Pages 무료 플랜에서 게시됩니다.)

**2. 원격을 연결하고 push 합니다**

```bash
git remote add origin https://github.com/yongjun96/resume.git
git push -u origin main
```

**3. Pages를 켭니다**

저장소 **Settings → Pages → Source: Deploy from a branch → Branch: main / (root) → Save**

1~2분 뒤 <https://yongjun96.github.io/resume/> 에서 열립니다.
이후에는 `git push` 만 하면 자동으로 반영됩니다.

Netlify / Vercel / Cloudflare Pages를 쓰는 경우에도 빌드 명령 없이 이 폴더를 그대로 배포하면 됩니다.

### 공개 범위 설정

- `robots.txt` 와 각 페이지의 `<meta name="robots" content="noindex, nofollow">` 로 **검색엔진 색인을 차단**했습니다.
  링크를 직접 아는 사람만 열람하는 것을 전제로 합니다.
- 다만 robots.txt는 규칙을 지키는 크롤러에만 적용됩니다. 이메일과 전화번호를 수집하는 스팸 봇은
  이를 무시하므로, 연락처가 노출되는 것 자체를 막지는 못합니다.
- 공개 저장소이므로 `assets/` 의 원본 PDF와 프로필 사진도 URL을 알면 직접 내려받을 수 있습니다.
- 재직 중인 회사의 내부 프로젝트 내용이 포함되어 있습니다. 사내 호스트명과 저장소 경로, 커밋 수 등
  식별 정보는 제외했지만, 공개 전에 회사 정책과 충돌하지 않는지 한 번 확인하는 것을 권합니다.

### 비공개로 두려면

GitHub Pages는 무료 플랜에서 비공개 게시를 지원하지 않습니다. 링크를 받은 사람만 보게 하려면
Netlify의 사이트 보호(비밀번호) 기능이나 Cloudflare Access를 쓰는 편이 확실합니다.

## PDF로 저장

각 문서 페이지 우측 상단의 **PDF로 저장** 버튼(또는 `Ctrl + P` / `⌘ + P`)을 누르면 현재 HTML 문서를
그대로 PDF로 내려받을 수 있습니다. 인쇄 창에서 대상을 `PDF로 저장`으로 선택하면 됩니다.

인쇄 전용 스타일이 적용되어 다음이 자동 처리됩니다.

- 상단 내비게이션 · 하단 이동 링크 숨김
- A4 용지 / 여백 12mm 고정
- 섹션 라벨 색상 유지 (`print-color-adjust: exact`)
- A4 폭에서도 프로필 사진·기술 스택 표가 데스크톱 배치를 유지

### 페이지 나눔 규칙

원칙은 **쪼개면 의미가 깨지는 것만 통째로 유지**하는 것입니다. 목록 전체에 `break-inside: avoid`를 걸면
열 몇 줄짜리 목록이 통째로 밀리면서 앞 페이지 하단이 통으로 비어버리기 때문입니다.

| 대상 | 처리 |
|---|---|
| 도식(`.figure`), 참여인원 3줄(`ul.meta`), 기술 스택 표(`.stack`), 기타 프로젝트 박스, 병역/학력 | 통째로 유지 |
| 본문 목록(`ul.bullets`, `ol.ordered`) | 페이지를 넘나들되 **항목 하나는 잘리지 않게** |
| 문단·항목 | `orphans: 2` / `widows: 2` — 첫·끝 줄이 홀로 떨어지지 않게 |
| 제목류(섹션·프로젝트·회사·라벨·소제목) | `break-after: avoid` — 제목만 페이지 끝에 남지 않게 |
| 도식 크기 | 인쇄에서는 판독 최소 크기까지 축소해 통째로 밀려나는 빈도를 낮춤 |

`.stack`은 grid라 `dt`/`dd`만 보호하면 짝이 갈라져 마지막 행이 홀로 넘어가므로 표 전체를 묶었습니다.

측정 결과 마지막 장을 제외한 모든 페이지의 하단 공백이 **18% 이내**이며, 도식·표가 잘리는 지점은 없습니다.

브라우저 인쇄 방식을 쓰는 이유는 텍스트가 이미지로 변환되지 않아 **선택·검색·하이퍼링크가 그대로 살아있는**
PDF가 만들어지기 때문입니다(html2canvas 계열 라이브러리는 전체를 이미지로 변환해 용량이 커지고 텍스트 선택이 불가능합니다).

원본 PDF는 `assets/pdf/` 또는 각 페이지의 **PDF 원본** 버튼에서 내려받을 수 있습니다.
